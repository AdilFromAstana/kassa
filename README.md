# iiko-pos — мок-фронт кассы (iikoFront-style)

Тач-POS касса для сети общепита (🇰🇿 Казахстан). **Веб-SPA** (React + Vite + TS + Tailwind), визуально и по флоу повторяет кассу iikoFront. Сейчас — **полностью мок** (данные и логика в браузере, без сервера). Позже:
- встраивается в **Electron** как веб-страница (открывается одна страница на весь экран);
- бэкенд — **.NET** (мок-слой заменяется на API-вызовы).

📖 **Полная архитектура, связь фронт↔бэк и принципы — в [ARCHITECTURE.md](ARCHITECTURE.md). Читать перед работой.**

Спецификация-источник (реверс реальной iiko): `../iiko_spec/` (особенно `FRONT_01/02/03`, `SETTINGS_REGIME_AND_PRECHECK.md`, карта переходов и рабочие сценарии).

## Запуск

```bash
npm install
npm run dev      # http://localhost:5180
npm run build    # сборка статики в dist/ (для Electron)
npm run preview  # предпросмотр прод-сборки
```

PIN-коды (мок): Петров `1111` (Кассир/Менеджер), Иванова `2222` (Официант), Легасов `3333`, Админ `0000`.

## Реализованные флоу (по ролям)

1. **Вход** — экран PIN (4 цифры) → выбор должности → **открытие личной смены**.
2. **Доп. меню** (КАССА / ГОСТИ / СЕРВИС / ПЕРСОНАЛ) — `MainMenuScreen`.
3. **Открытие кассовой смены** (без неё заказы недоступны).
4. **Схема зала** — выбор зала/стола → ввод кол-ва гостей → заказ. Занятый стол открывает существующий заказ. Быстрый чек — заказ без стола.
5. **Рабочий экран заказа** — быстрое меню (3 страницы, группы→блюда), добавление позиций, **модификаторы** (мин/макс), количество (`+ − 123`), скидка (`⋮`), удаление (`✕`), пречек.
6. **Расчёт/оплата** — типы оплаты (наличные/карта/безнал/без выручки/бонус), **разбивка суммы**, сдача → **фискальный чек (мок Webkassa)** с БИН, ҚҚС 16%, ФД.
7. **Личная страница** — итоги работы, заработок, закрытие личной смены.
8. **Закрытие кассовой смены** — мастер: незакрытые заказы → контрольный пересчёт → отчёты → **Z-отчёт**.
9. **Отчёты на кассе** — X-отчёт, 041/043/045/048/052 (цифры из закрытых заказов, внесений/изъятий, возвратов).
10. **Банкеты и резервы** — список с фильтрами + смена статуса (Пришёл/Снят) + **создание** карточки резерва/банкета.
11. **Внесение / изъятие денег** — типы операций, учитываются в пересчёте смены и отчёте 052.
12. **Закрытые заказы + возвраты** — частичный/полный возврат (возвратный чек), изменение типа оплаты, печать товарного.
13. **Деление счёта по гостям** — назначение позиций гостям (Г1/Г2…), оплата по каждому гостю отдельным чеком.
14. **Перенос / объединение заказа** — на свободный стол или слияние с заказом другого стола.
15. **Чек коррекции** — форма (признак расчёта, тип коррекции, СНО ОУР/СНР, ставка ҚҚС, суммы) → печать через ОФД.

## Архитектура

```
src/
├─ screens/        экраны (по одному на флоу)
├─ components/      TopBar, NumPad, ModifiersModal
├─ store/pos.ts     zustand — состояние смены/заказа/оплат + вся бизнес-логика (мок)
├─ mock/           menu.ts (меню+модификаторы), data.ts (сотрудники, столы, типы оплат)
├─ lib/money.ts     формат ₸ и расчёт ҚҚС 16%
├─ types.ts         доменные типы
└─ router.tsx       HashRouter (работает как file:// в Electron)
```

**Точка интеграции с .NET:** весь доступ к данным сосредоточен в `store/pos.ts` и `mock/*`. Когда появится API — заменить мок-функции (`login`, `startOrder`, `pay`, отчёты, справочники меню/столов) на `fetch` к .NET-бэкенду; экраны и флоу не меняются.

**Под Electron:** `vite build` → `dist/` (статика, `base: './'`, HashRouter). Electron-обёртка грузит `dist/index.html` в `BrowserWindow` (kiosk/fullscreen). Фискальный слой (Webkassa/драйвер ФР) подключается на стороне Electron/.NET.
