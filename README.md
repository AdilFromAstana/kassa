# iiko-pos — мок-фронт кассы (iikoFront-style)

> **Standalone git-репозиторий** в `work/iiko-pos` (в один ряд с `ntchat-clone`, `prime-ticket-*`). Веб = источник истины; позже Electron + .NET — отдельными репо рядом.
> **Таргет — iikoFront 9.x.** Спека-реверс `../iiko_spec/` снята с 8.5; известные дельты 8.5→9.x и пробелы паритета — в [PARITY_AUDIT.md](PARITY_AUDIT.md) (средний паритет ~45%).

Тач-POS касса для сети общепита (🇰🇿 Казахстан). **Веб-SPA** (React + Vite + TS + Tailwind), визуально и по флоу повторяет кассу iikoFront. Сейчас — **полностью мок** (данные и логика в браузере, без сервера). Позже:
- встраивается в **Electron** как веб-страница (открывается одна страница на весь экран);
- бэкенд — **.NET** (мок-слой заменяется на API-вызовы).

📖 **Полная архитектура, связь фронт↔бэк и принципы — в [ARCHITECTURE.md](ARCHITECTURE.md). Читать перед работой.**

Спецификация-источник (реверс реальной iiko): `../iiko_spec/` (особенно `FRONT_01/02/03`, `SETTINGS_REGIME_AND_PRECHECK.md`, карта переходов и рабочие сценарии).

## Запуск

```bash
npm install
npm run dev      # http://localhost:5180
npm run build    # сборка статики в dist/ (для Electron)
npm run preview  # предпросмотр прод-сборки
```

PIN-коды (мок): Петров `1111` (Кассир/Менеджер), Иванова `2222` (Официант), Легасов `3333`, Админ `0000`.

## Реализованные флоу (по ролям)

1. **Вход** — экран PIN (4 цифры) → выбор должности → **открытие личной смены**.
2. **Доп. меню** (КАССА / ГОСТИ / СЕРВИС / ПЕРСОНАЛ) — `MainMenuScreen`.
3. **Открытие кассовой смены** (без неё заказы недоступны).
4. **Схема зала** — выбор зала/стола → ввод кол-ва гостей → заказ. Занятый стол открывает существующий заказ. Быстрый чек — заказ без стола.
5. **Рабочий экран заказа** — быстрое меню (3 страницы, группы→блюда), добавление позиций, **модификаторы** (мин/макс), количество (`+ − 123`), скидка (`⋮`), удаление (`✕`), пречек.
6. **Расчёт/оплата** — типы оплаты (наличные/карта/безнал/без выручки/бонус), **разбивка суммы**, сдача → **фискальный чек (мок Webkassa)** с БИН, ҚҚС 16%, ФД. При оплате **списываются ингредиенты со склада** по техкарте блюда **и его модификаторов** (гарнир/молоко/сироп).
7. **Личная страница** — итоги работы, заработок, закрытие личной смены.
8. **Закрытие кассовой смены** — мастер: незакрытые заказы → контрольный пересчёт → отчёты → **Z-отчёт**.
9. **Отчёты на кассе** — полный список **011–054** по разделам 01–04 (как в iikoFront), окно **«Параметры»** (период + тач-календарь) для отчётов 01–03, «Обновить», «Печать». Цифры — из закрытых заказов, внесений/изъятий, возвратов.
10. **Банкеты и резервы** — список с фильтрами + смена статуса (Пришёл/Снят) + **создание** карточки резерва/банкета.
11. **Внесение / изъятие денег** — типы операций, учитываются в пересчёте смены и отчёте 052.
12. **Закрытые заказы + возвраты** — частичный/полный возврат (возвратный чек), изменение типа оплаты, печать товарного.
13. **Деление счёта по гостям** — назначение позиций гостям (Г1/Г2…), оплата по каждому гостю отдельным чеком.
14. **Перенос / объединение заказа** — на свободный стол или слияние с заказом другого стола.
15. **Чек коррекции** — форма (признак расчёта, тип коррекции, СНО ОУР/СНР, ставка ҚҚС, суммы) → печать через ОФД.

## Архитектура

```
src/
├─ screens/        экраны (по одному на флоу)
├─ components/      TopBar, NumPad, ModifiersModal
├─ store/pos.ts     zustand — состояние смены/заказа/оплат + вся бизнес-логика (мок)
├─ mock/           menu.ts (меню+модификаторы), data.ts (сотрудники, столы, типы оплат)
├─ lib/money.ts     формат ₸ и расчёт ҚҚС 16%
├─ types.ts         доменные типы
└─ router.tsx       HashRouter (работает как file:// в Electron)
```

**Точка интеграции с .NET:** весь доступ к данным сосредоточен в `store/pos.ts` и `mock/*`. Когда появится API — заменить мок-функции (`login`, `startOrder`, `pay`, отчёты, справочники меню/столов) на `fetch` к .NET-бэкенду; экраны и флоу не меняются.

**Под Electron:** `vite build` → `dist/` (статика, `base: './'`, HashRouter). Electron-обёртка грузит `dist/index.html` в `BrowserWindow` (kiosk/fullscreen). Фискальный слой (Webkassa/драйвер ФР) подключается на стороне Electron/.NET.

## 🇰🇿 KZ-контекст
Тенге ₸, НДС (ҚҚС) 16%, БИН/ИИН, фискализация Webkassa. Чек — мок формата КЗ.

## Паритет с реальным iikoFront 9.x
Полный аудит по 22 экранам — в [PARITY_AUDIT.md](PARITY_AUDIT.md) (средний паритет ~45%; бэклог high-приоритета). ⚠️ adversarial-verify прерван лимитом сессии — находки ❌/➕/🆕 = кандидаты, перепроверять перед правкой. См. раздел «Отклонённые находки» (напр. ставка ҚҚС 16% — верна, не дефект).

✅ **Tier 1 закрыт:** стоп-лист с остатком/кто/когда (тает при оплате, при 0 → стоп), сервисный чек на кухню/бар (весь заказ / выделенное), пречек (был на экране заказа).
✅ **Права доступа (F_*):** модель `lib/rights.ts` (право по должности). Стоп-лист гейтится `F_EM`, возврат — `F_STRN`/`F_SWWOFF`; нет права → блок/прокатка карты менеджера.
✅ **Возврат как флоу (Tier 2 #4):** возврат привязан к закрытому чеку — причина + режим «на склад» (возврат ингредиентов) + авторизация правом/картой менеджера. Частичный (выбор позиций) и полный — и в **ClosedOrders**, и в **ClosedShifts** (архив смен, `StornoPastOrderItems`). Требует **открытой кассовой смены** (как в iiko — возврат на ФР текущей смены). «Чек коррекции» отделён от возврата (фискальная коррекция KZ). Не сделано: проверка наличности в ящике при возврате наличными.
✅ **Документы на кассе (Tier 2 #5):** раздел «Документы» (СЕРВИС) — акт списания (с причиной), приготовления, переработки, внутр. перемещение, расходная, инвентаризация. Каждая операция = документ (история + движение остатков; инвентаризация выставляет факт). Из Warehouse убран выдуманный «Приход» (приходной накладной на терминале нет — это офис); Warehouse теперь только просмотр остатков/техкарт.
✅ **Фискальный чек до оплаты (Tier 3, 9.x):** настройка `fiscalBeforePay` (из офиса, по умолч. выкл). Когда вкл — на экране оплаты вместо «Оплатить» кнопка **«Фискальный чек»**: печать ФД на полную сумму с типом оплаты, стол **не закрывается**, заказ → статус `fiscalized`; затем «Закрыть заказ» принимает оплату. Правило iiko с 01.03.2025.
✅ **Экран заказов в 3 режима (Tier 3):** на экране «Заказы» (HallScreen) переключатель внизу справа — **Схема зала** (план столов по залам), **Все столы** (все залы сразу), **По официантам** (открытые заказы по сотруднику).
✅ **Права F_* по экранам (Tier 3):** карта `lib/rights.ts` по `iiko_spec/PERMISSIONS.md` (Официант/Бармен/Кассир/Менеджер). Гейты: открытие/закрытие смены (F_OCS/F_CS), внесение/изъятие (F_CASH), X-отчёт (F_XR), возврат (F_STRN), чек коррекции (F_OCS), отчёты (F_VRPT), явки (F_CVS), ручная скидка/надбавка (F_ID). Официант видит, но не может кассовые/денежные/скидочные операции.
✅ **Бэк-офис (мок) + Front-разделение:** добавлен раздел **`/office`** (iikoOffice-мок, светлая админка) — здесь правится конфиг заведения (режим, фичи, фискальный чек до оплаты, число ФР). Общий стор + localStorage → касса (Front) читает конфиг и применяет сразу. Вход: на экране входа ссылка «Бэк-офис», обратно — «Открыть кассу (Front)». Так «как в айке»: заведение настраивается в офисе, касса только потребляет. Полноценный офис (меню/цены/техкарты/сотрудники) — отдельные разделы на будущее (в сайдбаре помечены «скоро»).

✅ **Settings исправлен (как в айке):** till-«Настройки заведения» → **только просмотр** конфига (из офиса) + кнопка «Открыть Бэк-офис»; демо-генератор вынесен в явную дев-панель. Добавлен реальный терминальный экран **«Настройка оборудования»** (`/equipment`, Инструменты): ФР/ОФД Webkassa, принтер чеков, денежный ящик, весы — со статусом и «Проверить связь». Убран выдуманный пункт «Настройки терминала» и `alert`-заглушка.

✅ **Офис: «Меню и цены»:** в `/office` раздел редактирования цен меню (слой `priceOverrides` в сторе + localStorage `iiko-menu-prices`). Поменял цену в офисе → касса применяет к новым позициям и показывает в меню/поиске (`pos.priceOf`). Доказывает архитектуру офис→касса на центральной сущности.

✅ **Офис: «Сотрудники и права»:** карта роль→права переведена в стор (`roleRights` + localStorage `iiko-role-rights`, дефолт из `PERMISSIONS.md`). В офисе — список сотрудников + **матрица должность×право** (галочки), правится → касса применяет сразу (`can`/`hasRightFor` читают стор; RefundModal тоже). Замкнута петля: роли задаются в офисе, касса enforce'ит.

✅ **Офис: «Номенклатура и техкарты»:** товары на складе с приходом (`receiveStock`) и правкой факта/инвентаризацией (`setIngredientStock`) — офисный контур (на кассе приход убран); техкарты — просмотр (себест./доступно/состав). Касса списывает по ним при продаже. Склад↔меню связаны.

✅ **Слабые экраны фронта подтянуты:** **PersonalPage** — результат работы по датам + итоги месяца (ЛП/СПЧ); **Attendance** — приём явки, типы (отработано/прогул/отпуск/больничный), добавить/удалить, кнопка «Личная страница»; **Messages** — важные красным, сообщения в сторе + **конверт в TopBar** с бейджом непрочитанных (на каждом экране).

✅ **Офис: «Отчёты»:** сводка по смене (выручка/чеки/средний/возвраты, по типам оплаты, топ блюд, число складских документов) — последний раздел сайдбара. Офис закрыт по всем разделам.
✅ **Аудит логики (headless, 21/21):** прогон стора через esbuild подтвердил: права из офиса→касса, цены-оверрайды, списание модификаторов, возврат на склад, акт списания/инвентаризация, стоп-лист с остатком, фискальный чек до оплаты, сообщения. (Гейт «открытая смена» для возврата — UI-уровень, не в сторе.)

✅ **Редактирование техкарт из офиса:** слой `techCardOverrides` (стор + localStorage `iiko-techcards`); в офисе «Номенклатура и техкарты» — редактор рецепта (ингредиент/норма/добавить/убрать). Касса списывает по новой техкарте (`applyWriteoff`/`applyRestock`/`dishCost`/`dishMaxPortions` принимают оверрайды). Проверено headless (3/3).
