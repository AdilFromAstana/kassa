# ADMIN_BACKOFFICE_SPEC.md — UI админки/бэк-офиса (мультиклиент SaaS)

> Что нарисовать во фронте для мультиклиентной модели (см. `BACKEND_DESIGN.md` §3, `BACKEND_PLAN.md` Фаза 2).
> Продукт — SaaS: много клиентов-сетей → точки → сотрудники. Текущий `/office` в моке — одноклиентный; над ним добавляется уровень **сеть/структура** + онбординг.

## Роли и их интерфейсы

| Роль | Вход | Что видит/делает |
|---|---|---|
| **PlatformAdmin** (ты) | email/пароль (платформа) | реестр клиентов-сетей, создание/блокировка, тариф, вход «как клиент» |
| **Owner / офис** (клиент) | email/пароль (tenant) | сеть, точки, сотрудники, каталог, цены по точкам, отчёты — в рамках своей сети |
| **Staff** (POS) | PIN/карта (точка) | касса iikoFront (уже есть) — НЕ бэк-офис |

## A. Платформенная админка (PlatformAdmin)
- **Клиенты (реестр сетей):** таблица tenant'ов (название, БИН, тариф, кол-во точек, статус active/blocked, дата). Действия: создать клиента (+владельца), заблокировать, открыть, «войти как клиент».
- **Создание клиента (admin-режим онбординга):** форма «Сеть + владелец» (название сети, БИН, email/имя владельца) → создаёт `tenant` + `app_user`(owner) → ссылка-приглашение/пароль.

## B. Онбординг клиента (оба режима)
1. **Self-serve регистрация** (публичная): форма «Создать сеть» — название, email, пароль, БИН → `POST /api/auth/register` → `tenant`+owner → мастер первого запуска.
2. **Admin-создание** (см. A) → владелец получает доступ.
3. **Мастер первого запуска (owner):** шаг 1 — данные сети; шаг 2 — создать первую точку (ТП); шаг 3 — завести сотрудников; шаг 4 — каталог (импорт/из шаблона). Можно пропустить и делать позже.

## C. Бэк-офис клиента (Owner/офис) — разделы

### C1. Структура сети (новый раздел, над текущим /office)
- Дерево: **Юрлицо → Подразделение → ТП (точка) → Склад** — CRUD (на базе `corp_*`).
- Карточка точки (ТП): название, юрлицо, адрес, профиль заведения (`establishment`: режим/фичи), активна/нет.
- **Переключатель точки** в шапке офиса — большинство экранов работают в контексте выбранной ТП (цены, склад, смены, отчёты), каталог — на уровне сети.

### C2. Сотрудники и доступы
- **Офисные пользователи** (`app_user`): email, роль, **скоуп = вся сеть или набор ТП**, активность. Приглашение по email.
- **POS-сотрудники** (`staff`): имя, PIN, карта, должности, **привязка к точке**.
- **Матрица прав** (роль → права `F_*/B_*/D_*`) — как в моке (`OfficeScreen` права), но в рамках сети.

### C3. Каталог сети (общий, наследуется точками)
- Номенклатура/блюда, группы меню, модификаторы, техкарты (ТТК), типы оплат/заказов, дисконт/лояльность, концепции, план счетов. — Это **уровень сети** (редактируется один раз, видно на всех точках). Существующие экраны офиса переносятся сюда.

### C4. Цены и ассортимент — ПО ТОЧКЕ
- Экран «Прейскурант»: выбор точки (или ценовой категории) → список блюд с **базовой ценой сети** и **полем переопределения для точки**; приказы об изменении цен (`price_order`).
- **Ассортимент точки** (`point_dish`): какие блюда сети продаются на этой точке (вкл/выкл), стоп-лист.
- Явно показать: «цена сети vs цена точки» (разные цены на разных точках — штатно).

### C5. Склад — ПО ТОЧКЕ
- Остатки `stock_balance` по складам выбранной точки (карточка товара — общая на сеть, остаток — свой).
- Накладные/приход, документы (списание/перемещение/инвентаризация), задолженность поставщикам.

### C6. Отчёты — ПО ТОЧКЕ / по сети
- Продажи, OLAP, бухгалтерия/проводки, ДДС, ЗП — фильтр по точке или консолидировано по сети.

## Что меняется в текущем фронте (iiko-pos)
- Над `/office` появляется **контекст сети + переключатель точки**; экраны делятся на «уровень сети» (каталог) и «уровень точки» (цены/склад/смены/отчёты).
- Добавляются: страница входа офиса (email/пароль), регистрация сети (self-serve), платформенная админка (отдельный раздел/поддомен), управление офисными пользователями.
- Касса (iikoFront) почти не меняется — она уже в контексте одной точки; добавится только tenant/point из токена.

## API (где брать) — детали в BACKEND_DESIGN §3/§5
- Онбординг: `POST /api/auth/register`, `POST /api/tenants` (admin), `POST /api/points`, `POST /api/staff`, `POST /api/users` (office).
- Auth: `POST /api/auth/login` (офис email/пароль), `POST /api/auth/pin`, `/card` (POS), `POST /api/auth/refresh`.
- Каталог (сеть) и цены (точка): CRUD-эндпоинты Фазы 3.
